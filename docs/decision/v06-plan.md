# Decision v0.6 — data coverage and model capacity

Status: completed, authorized 2026-10-19. See [measured outcomes](v06.md), [correctness audit](v06-binding-audit.md) and the subsequent [85% development-policy amendment](v06-diagnostic-policy.md). The original frozen plan remains archived with its hashes. This round explicitly includes larger data and larger models within the local GPU memory limit. It preserves [v0.5](v05.md) and the delivered v0.1 preview. All outcomes, including resource failures and nonqualifying models, must be retained. The goal is a reproducible qualified improvement or a conclusion limited to the tested scales and resources.

## Questions and controls

Compare the same separate/RoPE recipe at 32 versus 512 independent controlled worlds per language and at two measured feasible model sizes. The four-cell factorial separates data, capacity and their interaction. Larger datasets are nested subsets of a frozen 512-world training reservation. Development, calibration and test allocations derive from that maximum reservation, not the active training subset; no fixed split offsets or modulo reuse of exhausted worlds.

Keep width 256, the own v0.1 tokenizer and original parent. Candidate capacity profiles are base (4 encoder blocks, FFN 768), medium (8 blocks, FFN 1536), and large (12 blocks, FFN 2048). Add identity residual blocks and zero-output FFN extensions so initial outputs agree with the parent. Fresh optimizers for every experiment. This tests depth/FFN capacity with matched inherited functions, not a width sweep or pretrained-model comparison. Confirm that added units receive gradients after the preserved initial step.

## Memory and finite budget

The observed Quadro RTX 3000 has 6,144 MiB total. Keep a **4,096 MiB per-process budget**, FP32, effective batch 32, CUDA training. Probe full configured input limits with 2, 3 and 18 candidates, backward passes and allocated AdamW state. Start at microbatch four; reduce to two or one if needed, preserving effective batch. Resource errors are not negative learning results. A CPU fallback invalidates a CUDA capacity trial. Report sampled memory honestly; samples are not a continuous peak. Choose the largest profile passing all probes; retain medium/base results even if large fails. If only base fits, record that limit and execute the data comparison.

Pre-training resource amendment: controlled binary corpora have audited maximum input lengths much shorter than the configured API limits. In addition to full-shape probes, test binary controlled training at rounded-up observed maxima and common microbatch 16, reducing if needed. Both capacities use the same feasible controlled microbatch. All frozen training rows must fit these audited bounds; no truncation or change to numerical inputs is allowed. The later long-input/natural/routing stage uses its separately qualified full-shape microbatch. This avoids imposing the 18-candidate worst-case microbatch on a stage containing only short two-candidate examples. It changes resource scheduling, not data or learning gates, and is declared before any learning run.

The entire round permits at most **30,000 successful experimental optimizer updates**, including preflight and replayed updates. Reserve at most 300 for memory probes. Initial controlled screens use 1,500 updates per factorial cell. If more than one enlarged profile fits, only the largest enters the initial factorial. A 128-world base midpoint (1,500 updates) is conditional on the observed data trend needing resolution. The two 512-world cells may extend to 4,000 total updates each when training remains incomplete or development still improves; freeze this decision from their initial results before extending. No completed failed budget is silently reinterpreted.

Concrete extension rule: after all four initial screens, extend both 512-world capacities together if either has not passed two consecutive known-mastery checks, or its canonical worst-language balanced accuracy gains at least 0.02 between updates 1,000 and 1,500, or its worst actor/event group gains at least 0.05. Run the base 128-world midpoint only if the two capacities' 512-minus-32 canonical data effects have opposite signs and both magnitudes are at least 0.03. Initial comparisons match updates and example visits; token counts, padding, time and memory are recorded, and unequal model FLOPs are not called compute-matched.

Select a controlled recipe using fixed development metrics; do not open acceptance. If it passes known training mastery, allow at most two 3,000-update follow-up curricula comparing the selected capacity with the base counterpart on the same expanded data. These may expand reviewed natural supervision and expression coverage, with independent splits and documented deficits, and then introduce unknown judgments while preserving known replay. Record those changes as a new recipe, not an isolated capacity effect. A development-qualified final recipe receives a second-seed full-recipe confirmation, at most 7,000 additional updates. The shared 30,000 ceiling takes precedence over all conditional allocations. Unused budget is not an instruction to continue searching.

## Data and qualification

Controlled worlds retain all four independent truth assignments, both claims and both record orders in training. Gold derives only from explicit actor/event facts; metadata never enters the neural input. Reserve same-vocabulary new combinations, new actor identities and held event slices separately; report them independently. Audit complete contrast groups, material/family overlap, absent/present actor exposure, tokens, duplicates and truncation. Default v04 generator output must remain compatible while custom split offsets derive from counts. String/symbol enum values are accepted.

Before learning, reject the first generated draft after its cross-round audit finds 12 test record materials matching previous panels (260 train, four development, zero calibration materials also overlap). Preserve it under `rejected-overlap/`. The replacement uses a natural-name pool disjoint from the legacy controlled names, and must pass conservative literal-material exclusion against all earlier local Decision data panels. This changes the round's shared vocabulary before any factorial cell trains; it is not an acceptance-informed correction. Individual token familiarity in the original parent remains possible and is not represented as unseen pretraining vocabulary.

Known training mastery requires balanced accuracy >=95% and actor **and** event complete-group correctness >=90% in each language at two consecutive checks. Controlled binary development requires balanced accuracy >=75%, actor/event groups each >=50%, and >=5-point gain over the own parent per language. A final factual preview also requires natural accuracy >=65% in each language and no >3-point parent regression. Three-state recall for every class must be >=70% in each language, with the relation/natural guards retained. Full-recipe confirmation must pass the same profile. Training probes are samples, not full-training accuracy.

Canonical, seen-actor/unseen-combination, and novel-actor panels must each pass the controlled development floors; the seen-combination panel records only actors present in the smallest training subset and uses no reserved canonical world. This prevents vocabulary-coverage gains from being misreported as compositional generalization. New-event results are a separate diagnostic and do not authorize unmeasured vocabulary claims. The fixed training probe covers 16 worlds per language (1,024 binary rows), sampled independently of model predictions.

Calibration and acceptance stay inaccessible until selection and confirmation pass. Freeze any newly reserved panels before training; already observed v05 development is regression only. Evaluate reserved acceptance once with fixed checkpoints, profiles and calibration. Publish only if both primary and confirmation meet the fixed floors; otherwise preserve the negative conclusion and v0.1. All narrower controlled-only successes must be labelled accordingly.
